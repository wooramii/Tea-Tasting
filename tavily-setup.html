Tavily 제품 검색 연결

한 번 설정하면 다른 사용자도 각자의 기록을 유지하면서 같은 검색 기능을 사용할 수 있습니다. 검색 사용량은 운영자님의 Tavily 계정에서 함께 차감됩니다.

먼저 준비할 것

  1. Tavily에 가입하고 로그인합니다. 무료 제공량으로 시작하고 유료 자동 충전은 켜지 않습니다. 2026-11-20 공식 안내는 월 1,000크레딧 무료이며 기본 검색 1회는 1크레딧입니다. 재검색·다른 사용자의 검색도 사용량에 포함됩니다.
  2. 대시보드에서 API Keys 메뉴를 찾아 키를 발급합니다. 키는 비밀번호처럼 보관하고 채팅·GitHub·HTML에 붙여넣지 마세요.
  3. Cloudflare에 가입합니다. 도메인 구매나 기존 사이트 이전은 필요하지 않습니다.

Cloudflare에서 검색 확인 기능 만들기

  1. Cloudflare의 Turnstile 메뉴에서 위젯을 추가합니다. 이름은 차곡 검색으로 지정합니다.
  2. 허용 호스트 이름에 wooramii.github.io를 입력합니다. https://나 /Tea-Tasting/는 넣지 않습니다.
  3. 위젯 유형은 Managed를 선택합니다.
  4. 생성된 Site Key와 Secret Key를 구분해 보관합니다. Site Key는 공개 가능하며 Secret Key는 공개하면 안 됩니다.

Cloudflare에 검색 중계 올리기

제공된 서버용 압축파일의 worker.mjs와 wrangler.jsonc 두 파일을 사용합니다. 아래는 GitHub 업로드를 이용하는 방법입니다.

  1. GitHub에 별도 저장소 chagok-search를 만들고 두 파일을 저장소 맨 위에 올립니다. 실제 API 키는 파일에 넣지 않습니다.
  2. Cloudflare에서 Workers & Pages → Create application을 선택하고 GitHub 저장소를 가져오는 항목을 선택합니다. 방금 만든 chagok-search 저장소만 연결합니다.
  3. 프로젝트 이름은 chagok-search, 루트 폴더는 기본값을 사용합니다. 빌드 명령은 비워두고, 배포 명령은 npx wrangler deploy로 설정해 배포합니다. 화면 명칭이 다르면 현재 화면을 확인한 뒤 진행하세요.
  4. 생성된 Worker에서 Settings → Variables and Secrets → Add를 찾습니다. 유형을 Secret으로 선택해 아래 두 항목을 추가합니다.
    • TAVILY_API_KEY: Tavily API 키
    • TURNSTILE_SECRET_KEY: Turnstile Secret Key
  5. 변경사항을 저장·배포합니다. 제공된 주소가 https://chagok-search.내계정.workers.dev라면 앱에서 쓸 검색 주소는 끝에 /search를 붙인 주소입니다. 주소를 브라우저에서 그냥 열면 접근 거부가 나오는 것이 정상입니다. 앱의 검색 요청만 처리합니다.

차곡 화면과 연결하기

  1. 화면용 압축파일에서 web-search-config.js를 메모장으로 엽니다.
  2. endpoint에는 Worker 검색 주소, siteKey에는 공개용 Turnstile Site Key를 넣습니다. 기존 Google config.js는 수정하지 않습니다.
window.TEA_WEB_SEARCH = {
 endpoint: 'https://chagok-search.내계정.workers.dev/search',
 siteKey: '공개용 Turnstile Site Key'
};
  1. 화면용 파일들을 기존 Tea-Tasting 저장소에 덮어씁니다. 서버용 두 파일을 여기에 올리는 것으로 서버가 실행되지는 않습니다.
  2. GitHub 배포가 끝나면 차곡에서 Ctrl + F5를 누릅니다.
  3. 제품명이나 바코드를 조회합니다. 내 기록·Open Food Facts에서 없으면 자동으로 웹 검색을 시도합니다. 결과가 있어도 웹에서도 제품 찾기를 누를 수 있습니다. 확인 화면이 나오면 직접 완료하세요.
  4. 웹 후보의 원문·포장·용량을 확인한 뒤 후보를 누르면 제품명과 명시된 용량, 원문 출처·조회 시각이 입력됩니다. 테이스팅 저장을 눌러야 개인 시트나 기기에 저장됩니다.

무엇이 자동 입력되나요?

Tavily는 상품 DB가 아닌 웹 검색입니다. 검색 제목을 제품명으로 사용하므로 판매처명이나 광고 문구가 포함될 수 있습니다. 제목에 용량이 한 가지로 명시된 경우에만 그 표기를 가져옵니다. 브랜드·이미지·원재료는 추측하여 넣지 않습니다. 기존 이미지·원재료 등은 유지하고, 관능점수·날짜·가격·노트·Brix·pH·산도는 바꾸지 않습니다. 다른 후보를 선택할 때 기존 브랜드·바코드가 남아 있다면 실제 포장과 대조해 수정하세요.

Google 검색과 Tavily 검색 결과는 다릅니다. 웹에서 바코드가 발견되어도 같은 제품이라고 단정하지 않습니다. 후보 원문에서 바코드가 확인되지 않으면 주의를 표시합니다. UPCitemdb·GS1은 바코드 전용 외부 조회 바로가기이며, GS1에서는 번호를 직접 입력합니다. 이 두 서비스의 결과를 자동 입력하지는 않습니다.

오류가 날 때

  • 연결 설정 전: web-search-config.js의 주소와 Site Key, 업로드 여부를 확인합니다.
  • 검색 확인 실패: Turnstile 허용 호스트와 두 키의 구분을 확인합니다.
  • 검색 연결 설정 확인: Worker의 Secret 이름과 저장·배포 여부를 확인합니다.
  • 사용량 도달: Tavily 대시보드를 확인합니다. 무료 계정에서 먼저 시험하며 자동 결제는 켜지 않습니다.
  • 키가 노출됐다면 Tavily/Cloudflare에서 해당 키를 폐기하고 새 키를 서버의 Secret에 저장합니다.

검색어는 Cloudflare 중계를 거쳐 Tavily로 전송됩니다. Google 연결 토큰과 개인 시트 기록은 전송하지 않습니다. Turnstile은 로그인 기능이나 엄격한 월 사용량 제한을 대신하지 않습니다. 공개 사용자가 많아지면 별도 사용자별 제한이 필요합니다.
