Tavily 웹 검색 추가 · 2026-11-20

가입부터 연결까지 순서대로 보기. 아래 기존 설명의 무료·무설정 조회 범위는 Open Food Facts입니다. 운영자가 Tavily를 연결하면 등록 제품이 없을 때 웹 검색을 시도하며, 「웹에서도 제품 찾기」로 추가 검색할 수 있습니다. 웹 후보는 한 번 누르면 검색 제목·명시된 용량·원문 출처·조회 시각이 입력됩니다. 실제 포장을 확인한 뒤 테이스팅 저장을 누르세요. 웹 검색은 Google과 결과가 다르며, 브랜드·원재료·이미지는 추측하여 넣지 않습니다. 관능점수·날짜·가격·노트·실측값은 유지합니다. GS1 조회는 바코드가 채워진 새 탭을 열며 결과 자동 입력은 지원하지 않습니다. 입력칸 옆 복사 버튼으로 바코드 숫자만 복사할 수 있습니다.

로그인 표시·새로고침·입력 초기화

Google 연결이 완료되면 로그인·연결 해제 버튼을 숨기고 연결 상태만 표시합니다. 연결이 만료되면 로그인 버튼이 다시 나타납니다. 상단 TEA TASTING LIBRARY·차곡 문구를 누르면 페이지를 새로고침합니다. 연결 토큰은 탭 메모리에만 보관하므로 페이지를 다시 불러온 뒤 Google 연결이 필요할 수 있습니다.

「새 테이스팅 → 입력 초기화」는 작성 중인 값만 비웁니다. 미저장 입력이 있으면 확인창에서 계속 입력하거나 초기화를 선택하세요. 테이스팅 날짜는 오늘, 분류는 티백, 관능항목은 미평가로 돌아가며 저장된 기록은 유지됩니다.

지금 바로 해보기

  1. 차곡 화면에서 제품명과 테이스팅 날짜를 입력합니다. 날짜는 한국 시간 기준 오늘이 기본값입니다.
  2. 관능강도를 1~9점으로 선택합니다. 1은 감지되지 않음, 5는 중간, 9는 매우 강함입니다. 미평가는 비워둡니다.
  3. 「테이스팅 저장」을 누르고 가운데 제품을 클릭합니다.
  4. 「같은 티 다시 기록」으로 다른 날짜의 평가를 추가합니다. 오른쪽에서 날짜별 기록을 볼 수 있습니다.
  5. 「백업 받기」로 기록을 보관하세요. 브라우저 기록 삭제·시크릿 모드 종료 시 기기 기록이 사라질 수 있습니다.

제품명·바코드로 정보 불러오기

  1. 제품명을 입력하고 「이름 조회」를 누르거나, 바코드를 입력하고 「조회」를 누릅니다. 카메라 스캔 성공 시에도 조회합니다.
  2. 내 기록과 Open Food Facts의 후보를 확인하고 제품을 선택합니다. 제품명·브랜드·용량·바코드로 같은 제품인지 대조하세요. 국내 제품이나 최근 출시품은 공개 DB에 없을 수 있습니다. 브랜드 또는 영문명으로도 검색할 수 있습니다.
  3. 미리보기에서 불러올 항목을 선택하고 「선택 정보 불러오기」를 누릅니다. 선택한 제품정보는 기존 값을 바꿉니다. 날짜·분류·평가점수·테이스팅노트·가격·Brix·pH·산도는 유지됩니다.
  4. 원재료 표기·이미지·용량 등을 실제 포장과 확인하고 테이스팅 저장을 누르면 출처·조회일과 함께 저장됩니다. 원재료 표기를 블렌딩 비율로 자동 해석하지 않습니다.

조회 자체에는 별도 API 키나 계정 등록이 필요 없습니다. 기존 Google 연결 권한도 그대로 사용합니다. 검색은 버튼을 누를 때만 외부로 요청하며 기록 전체와 Google 토큰을 보내지 않습니다. 미등록·오류·조회 한도 시 직접 입력할 수 있습니다. 데이터 제공자가 요청하는 앱 이용 등록은 Open Food Facts API 안내를 확인하세요.

제공 데이터: Open Food Facts · 데이터 ODbL/DbCL · 이미지 CC BY-SA. 공개 DB는 자발적 기여 정보로서 누락·오류가 있을 수 있습니다. 출처와 라이선스를 유지하고 외부 데이터 재배포 시 제공 조건을 확인하세요.

GitHub 배포

  1. GitHub에서 새 저장소를 만듭니다. 예: tea-library.
  2. tea-library 폴더 안의 파일을 저장소 최상위에 올립니다. index.html이 저장소 첫 화면에서 보여야 합니다.
  3. 저장소의 Settings → Pages → Deploy from a branch → main → /(root) → Save를 선택합니다.
  4. 배포가 끝나면 Pages에 표시되는 실제 주소를 엽니다. 보통 https://사용자명.github.io/tea-library/ 형태입니다.
  5. 이 링크를 다른 사람에게 주면 각자 기기 저장 모드로 바로 사용할 수 있습니다.

개인 Google 계정 연동: 배포 후 한 번 설정

앱 소유자만 아래 설정을 합니다. 방문자는 설정할 필요 없이 로그인·권한 허용만 하면 됩니다. 회사 계정은 조직 정책으로 차단될 수 있습니다.

  1. Google Cloud Console에서 프로젝트를 만듭니다.
  2. API 및 서비스 → 라이브러리에서 Google Sheets API와 Google Drive API를 각각 사용 설정합니다.
  3. Google Auth Platform에서 앱 이름, 연락 이메일을 설정합니다. 잠재고객은 외부(External)로 선택합니다.
  4. 데이터 액세스 권한으로 https://www.googleapis.com/auth/drive.file을 추가합니다. Drive 전체 접근 권한은 선택하지 않습니다.
  5. 클라이언트 → OAuth 클라이언트 만들기 → 웹 애플리케이션을 선택합니다. 승인된 JavaScript 원본에 https://사용자명.github.io를 입력합니다. 저장소 경로는 원본에 넣지 않습니다. 로컬 테스트용으로 http://localhost:8080도 추가할 수 있습니다.
  6. 발급된 클라이언트 ID를 config.js의 빈 따옴표 안에 넣고 GitHub에 업데이트합니다. 클라이언트 보안 비밀은 사용하지 않습니다.
  7. 테스트 중에는 본인의 Google 계정을 테스트 사용자로 등록합니다. 차곡에서 Google로 연결 → 권한 허용 → 기록 저장을 시험합니다.
  8. 전용 시트 차곡 Tea Library가 본인 Drive에 생성됩니다. 이 파일을 공개로 공유하지 마세요.
  9. 다른 사람에게 제한 없이 제공하려면 잠재고객의 게시 상태를 프로덕션으로 변경하고 Google이 요구하는 앱 정보·브랜드·도메인 관련 절차를 완료해야 합니다. 테스트 상태는 등록된 테스트 사용자만 연결할 수 있습니다. 실제 허용 여부는 계정과 Google 심사·정책에 따릅니다.

시트에서 직접 수정하기

「내 시트 열기」를 눌러 Records 시트의 기존 행을 수정합니다. 웹에서 「새로고침」하면 반영되며, 화면이 열려 있으면 60초마다 확인합니다. 첫 행 제목·열 순서·id는 바꾸지 마세요. 새 행을 직접 추가할 때는 기존 행을 복사한 뒤 id를 고유한 값으로 변경하고 제품명·분류·테이스팅일을 채우세요. 날짜는 2026-11-19처럼, 점수는 1~9의 정수 또는 빈칸으로 입력합니다. 이미지·구매 링크는 https 주소를 사용합니다.

같은 제품의 여러 기록은 분류와 바코드, 또는 분류·브랜드·제품명으로 묶입니다. 제품명을 바꾸려면 관련 기록도 같은 이름으로 맞추세요.

기기 기록을 Google로 옮기기

  1. Google 연결 전 「백업 받기」를 누릅니다.
  2. Google로 연결합니다.
  3. 「백업 불러오기」에서 방금 받은 파일을 선택합니다. ID가 같은 기록은 중복 추가하지 않습니다.

1차 버전의 범위

가능: 제품 등록, 날짜별 테이스팅, 관능강도 1~9점, 검색·날짜 필터, 수치 기반 유사도, 백업, Google 시트 연결 코드, 제품 이미지 URL, 구매 링크.

바코드: 수동 입력·USB 리더기를 지원합니다. 카메라 스캔은 HTTPS/localhost 환경에서 카메라 사용 권한이 필요합니다. Windows Edge 등 기본 BarcodeDetector가 없는 브라우저도 함께 배포한 ZXing 인식 모듈로 처리합니다. 미지원·차단 환경에서는 숫자를 입력하세요. 바코드 조회 후 후보를 확인하고 제품정보를 불러올 수 있습니다.

제품명·바코드 조회는 Open Food Facts에 등록된 정보만 제공합니다. 추후 기능: 사진 인식, 사진 파일 업로드, AI 자연어 의미 검색, 실시간 구매처·가격 검색. 내 컬렉션 검색은 입력한 문자열을 찾습니다.

테이스팅 기록은 전문 관능 패널 결과나 기기 분석치와 구분합니다. 유사도는 공통으로 평가한 관능항목의 거리이며 개발 성공 확률이 아닙니다. 다른 추출조건의 원점수는 주의해서 비교하세요.

바코드가 흐리거나 잘 읽히지 않을 때

  1. 카메라를 열면 지원 장치에서 연속 자동초점을 먼저 요청합니다. 한 번 자동초점만 지원하면 그 방식을 요청합니다. 카메라가 제공하지 않는 초점 기능은 소프트웨어로 만들 수 없습니다.
  2. 「현재 실제 영상」의 해상도를 확인하세요. 기본값은 고해상도를 우선 요청합니다. 목록에서 해상도를 바꾸면 실제 적용값을 다시 표시합니다. 범위에 포함된 해상도라도 가로·세로 조합은 지원하지 않을 수 있으며, 실패하면 기존 영상으로 계속 인식합니다.
  3. 자동초점이 맞지 않으면 「수동 초점」을 선택하고 슬라이더로 선명도를 조절합니다. 슬라이더를 놓으면 적용됩니다. 지원되지 않으면 초점 제어 미지원으로 표시됩니다.
  4. 카메라 해상도를 바꾸면 인식 엔진도 새 프레임 크기로 다시 시작합니다. 화면 크기만 늘리는 디지털 확대는 하지 않습니다. 가까이 붙이지 말고 가는 줄과 흰 틈이 선명해지는 거리를 찾으세요.

외부 검색 범위

「조회」는 내 기록·Open Food Facts와 설정된 Tavily에서 제품정보를 찾습니다. 바코드 검색은 번호 일치 증거가 있는 후보만 표시합니다. Google·네이버·쿠팡 버튼은 각 검색 사이트를 엽니다. 「GS1 조회」는 입력한 바코드가 채워진 GS1 페이지를 새 탭에서 열며 결과를 자동 입력하지 않습니다. 「복사」는 숫자를 클립보드로 복사하며 검색이나 저장은 하지 않습니다.

GS1 Korea의 자동 데이터 연동은 바코드 정보 제휴사업의 계약·이용 조건 협의와 API 인증정보가 필요합니다. 일반 웹 조회 기능은 API 사용권한을 대신하지 않습니다. GS1 Korea 제휴 안내

Edge에서 카메라가 열리지 않을 때

  1. 배포 주소를 열고 카메라 버튼을 누릅니다. 권한 창이 뜨면 사용할 카메라 접근을 허용하세요.
  2. 차단했다면 Edge 주소창의 사이트 정보 → 이 사이트에 대한 사용 권한 → 카메라 설정을 확인하고 페이지를 새로고침하세요.
  3. Windows 설정 → 개인정보 및 보안 → 카메라에서 카메라 접근과 데스크톱 앱의 카메라 접근을 확인합니다. 회사 정책으로 잠겨 있으면 IT 담당자에게 확인하세요.
  4. 카메라를 찾지 못하면 USB 웹캠·노트북 카메라 연결을 확인하고, 사용 중이라는 안내가 나오면 Teams·Zoom 등에서 카메라를 끕니다.
  5. 카메라가 여러 개면 스캔 창에서 선택합니다. 인식 모듈 오류라면 zxing-browser.min.js 파일도 GitHub에 올렸는지 확인하세요.

인식은 기기에서 처리하며 카메라 영상을 서버로 업로드하지 않습니다. 닫기·다른 탭으로 이동·페이지 종료 시 카메라를 중지합니다. 인식 후에는 바코드로 제품정보를 조회합니다.

데이터 처리

Google 비밀번호를 차곡이 받지 않습니다. 연결 토큰은 현재 탭 메모리에만 보관하며, 새로 열면 다시 연결합니다. 연결 해제는 시트를 지우지 않습니다. 기기 저장 기록은 이 브라우저에 남습니다. 제품 이미지 URL을 입력하면 이미지는 해당 주소에서 불러옵니다. 회사 기밀·개발정보를 개인 계정에 저장하기 전 회사 정책을 확인하세요.
